## Исправления после базового среза

### 1. Координация idle-троттлинга — PR #81

В исходном `IdleThrottle.ts` каждый вызов создавал собственный таймер и локальный `lastLimit`, хотя `scene.game.loop.setFPSLimit()` меняет общий цикл Phaser. При двух активных стационарных сценах завершение одной могло вернуть глобальные 60 FPS, когда другая уже не имела живого таймера, чтобы снова включить idle 15 FPS.

**Решение:** PR [#81](https://github.com/AiratGaliev/last-hero-medieval-survival/pull/81) добавил общий координатор, общий таймер и общий набор слушателей. FPS возвращается к 60 после shutdown последней зарегистрированной сцены. Добавлен unit-регрессионный тест на две активные сцены и программное закрытие overlay. PR слит; CI Fast [#40125943801](https://github.com/AiratGaliev/last-hero-medieval-survival/actions/runs/40125943801) — success.

### 2. Устаревшее описание bomb-fish

В `BootScene.ts` комментарий по-прежнему описывал самоподрыв рыбы, хотя код уже использует отдельный бомбовый снаряд. В PR #81 комментарий исправлен: bomb-fish бросает бомбу, остаётся в бою и использует собственную анимацию броска.

### 3. Неадресная паника соседних гражданских — PR #82

На базовом SHA `PawnAI.shouldFlee()` проверял `enemy.aimedPawn !== null`, то есть факт, что враг выбрал целью любую пешку. Поэтому соседний рабочий в радиусе паники мог убежать, хотя враг атаковал другого гражданского. Это останавливало экономику по ложному сигналу угрозы.

**Решение:** PR [#82](https://github.com/AiratGaliev/last-hero-medieval-survival/pull/82) изменил условие на `enemy.aimedPawn === p` и добавил Playwright-сценарий с двумя соседними гражданскими. PR слит; CI Fast [#40126179424](https://github.com/AiratGaliev/last-hero-medieval-survival/actions/runs/40126179424) — success. Сам E2E-сценарий ещё не исполнен на полном актуальном suite.

## Инвентаризация ассетов

В дереве на базе аудита найдены **608 PNG** и **3 WOFF2** (всего 611 файлов, около 4,68 МБ исходных данных). Распределение PNG соответствует базовой инвентаризации Tiny Swords: buildings — 40, enemies — 123, particle-fx — 8, resources — 30, terrain — 63, ui — 78, units — 228; производные `src/assets/game` — 38 PNG. `src/game/assets.ts` применяет eager `import.meta.glob` ко всем PNG, а `BootScene` загружает только ключи, реально нужные игре. Наличие файла в паке не означает его использование в рантайме; полный построчный отчёт по каждому исходному изображению как «используется/не используется» не заявляется.

## Остаточные блокеры и решения

1. **Полный E2E после правок PR #80 не повторён целиком.** Адресные rerun-сценарии после исправления фикстур не заменяют полный набор на итоговом SHA. Один desktop-сценарий `phase-p-juice` оставался flaky; перед QA-кандидатом необходимо повторить полный suite и разбирать фактический результат.
2. **Внешняя приёмка Yandex Games не подтверждена репозиторием:** ЕЛС, реальные SKU/цены/иконки, успех/отказ транзакции и восстановление pending receipt в Sandbox, а также alert по `iap_consume_fail`.
3. **Противоречие экономики крон требует решения владельца:** целевой темп 50–90 крон в неделю расходится с более старым расчётом примерно 125 крон/неделю. Выплаты не менять без единого согласованного таргета и теста ожидаемого дохода.
4. **Косметические title/frame сохраняются как entitlement, но в проверенных сценах не найден UX выбора и экипировки.** Либо добавить видимое применение в согласованный объём, либо исключить эти награды из релизного обещания.
5. **Не закрыты реальные мобильные и длинные игровые gates:** safe-area, touch-поведение, полный 15-минутный матч и измерение бюджета кадра на целевых устройствах.
6. `docs/ROADMAP.md` должен оставаться списком acceptance gates, а не превращать наличие класса или добавленного, но не запущенного теста в отметку о готовности.

## Решение по старту следующего спринта

Новые хотелки не нужно реализовывать параллельными крупными подсистемами. Сначала довести до зелёного быстрый CI этой ветки, затем выполнить полный браузерный suite на актуальном кандидате и актуализировать статусы по фактическим результатам. Первый функциональный инкремент из `docs/PLANS.md` §10.1 уже слит в PR #82: паника адресована фактической цели врага. Следом нужен полный E2E-кандидат и работа по issue [#83](https://github.com/AiratGaliev/last-hero-medieval-survival/issues/83), где согласуется приоритет угрозы против доставки груза. Не начинать одновременно кампанию, туман войны, дерево технологий и процедурные карты.

**Вердикт:** найденная ошибка координации FPS локальна и исправляется здесь. Проект можно продолжать развивать рабочими PR в `dev`, но он **не принят для продвижения `dev → test`**, пока не повторён полный актуальный E2E и не закрыты внешние релизные gates.

## Не проверено

- Локальные `npm run check`, `npm run test:unit`, `npm run build` и браузерный запуск в этом окружении: checkout невозможен из-за DNS-ошибки при обращении к GitHub. Проверки изменённой ветки должны быть выполнены CI.
- Фактическая Yandex Games Console/Sandbox, физические мобильные устройства и KPI из аналитики.
- Полный статический proof использования каждого из 608 PNG; эта проверка инвентаризирует пак и проверяет механизм загрузки, но не объявляет каждую картинку обязательной для рантайма.
