# Тайлмап Tiny Swords: как собирать карту уровня

Документ описывает, как устроены тайлсеты пака Tiny Swords (Pixel Frog) и как
из них правильно собирать карту игрового уровня в этом проекте.

Источник — официальный гайд автора:
<https://pixelfrog-assets.itch.io/tiny-swords/devlog/1138989/tilemap-guide>.
Всё, что ниже помечено «проверено», измерено по файлам в
`src/assets/tiny-swords/terrain/tileset/` скриптом на Node, а не взято «на
глаз» и не пересказано из гайда.

---

## 1. Что вообще есть в паке (проверено)

| Файл | Размер | Сетка | Что это |
|---|---|---|---|
| `tilemap-color1.png` … `tilemap-color5.png` | 576×384 | 9×6 тайлов по 64 px | набор деталей земли пяти цветов |
| `shadow.png` | 192×192 | 3×3 тайла по 64 px | тень под возвышенностью |
| `water-foam.png` | 3072×192 | 16 кадров по 192×192 | анимированная пена на границе воды |
| `water-background-color.png` | 64×64 | один тайл | цвет заливки воды (BG Color) |

Ключевой размер пака — **тайл 64×64**. Все координаты в гайде и в этом
документе считаются в этих единицах.

### Важная поправка к гайду

Гайд говорит, что Shadow и Water Foam — спрайты 128×128. В реальном паке
это не так: `shadow.png` это **192×192** (3×3 тайла), а кадр пены —
**192×192**. То же подтвердили и комментаторы под гайдом. Правило «спрайт
кладут на один тайл 64×64» остаётся верным — просто спрайт больше тайла
в три раза по каждой оси и свисает за границы на 64 px в каждую сторону.

### Это не автотайл, а набор блоков

`tilemap-colorN.png` — **не** классический автотайл (16/47 вариантов
кромок и углов). Это лист готовых многоклеточных кусков: массивные пятна
травы, полосы, углы и куски обрыва. Схема листа, разбитая по 64 px
(`.` — прозрачно, `G` — трава, `r` — камень обрыва, `o` — тёмный контур):

Читается так:

- **левая группа (столбцы 0–4)** — плоская земля у воды: большое пятно
  4×3 тайла, полосы и углы;
- **столбец 5** — прозрачный разделитель между группами;
- **правая группа (столбцы 6–8)** — то же сверху (пятно 3×3) и обрыв
  (серый камень) под ним: это «возвышенность»;
- нижние два ряда слева — треугольные куски с травой и камнем: это
  переходы между уровнями (лестницы и подводная часть обрыва).

Вывод для нас: **карта собирается из блоков, а не из клеток с авто-подбором
кромок.** Блоки непрозрачны между собой и уже содержат свои кромки, поэтому
нужно подбирать деталь под ситуацию (пятно, полоса, угол, обрыв) самому.

## 2. Правила из гайда (что нужно соблюдать)

1. **Слои.** Снизу вверх: BG Color (вода) → Water Foam → Flat Ground.
   Дальше пары Shadow + Elevated Ground повторяются столько раз, сколько
   уровней возвышенности. Разные цвета земли через слой делают высоту
   заметнее.
2. **Shadow.** Спрайт 192×192 кладётся на площадь тайла 64×64, то есть
   свисает на 64 px. Ставится **под** проходимой частью возвышенности и
   сдвинута ровно на один тайл (64 px) вниз — так получается иллюзия
   высоты и мягкая граница.
3. **Water Foam.** Ставится везде, где земля касается воды (BG Color).
   Чтобы пена не пульсировала синхронно, у соседних спрайтов анимация
   должна стартовать с разных кадров.
4. **Flat Ground.** Самый нижний уровень, примыкающий к воде. Набор деталей
   рассчитан на все типовые ситуации обрыва к воде.
5. **Elevated Ground.** Верхняя часть работает как Flat Ground, но сверху
   добавляются обрывы — и их **два вида**: один соединяет возвышенность с
   водой, другой — с проходимой землёй снизу.
6. **Stairs.** Соединяют нижний уровень с верхним. Если лестница стоит
   рядом с проходимой землёй и не рядом с обрывом, сверху нужен один
   центральный элемент возвышенности; если рядом с обрывом — две детали:
   одна соединяет верхнюю проходимую часть, другая — низ обрыва.

## 3. Как это ложится на наш код

### Слои и глубина

Свои константы глубины живут в `src/game/constants.ts` (`DEPTH`). Порядок
слоёв должен повторять гайд, иначе вода перекроет пену, а пена — землю:

```
DEPTH.WATER - 20   → вода (BG Color)
DEPTH.WATER + 2    → пена (Water Foam)
DEPTH.GROUND       → плоская земля (Flat Ground)
DEPTH.GROUND + 1   → кромка арены / первый слой тени
...                → дальше по одному слою на уровень: тень, потом земля
DEPTH.DECOR        → деревья, кусты, камни
```

### Что сделано сейчас

Арена в `GameScene.buildWorld()` собирается кодом, а не тайлмапом:

- вода — `tileSprite` с `water-tile` (тот самый BG Color), на весь мир;
- трава — `tileSprite` с производной текстурой `game/grass-tile.png`
  (ровная заливка без кромок);
- кромка арены — четыре `tileSprite` с одним кадром тайлсета
  (`shoreFrame = 5 * 9 + 6`), повёрнутыми на 90° друг к другу;
- пена — 130 случайных спрайтов `fx-foam` вдоль кромки (разброс по
  размеру, повороту и прозрачности);
- декор — деревья, кусты, камни, пни, овца и уточка, расставленные кодом.

То есть сейчас у нас ровно **один уровень земли без возвышенности**, и
тайлсет используется только для кромки. Полноценный тайлмап этим
заменяется.

### Три способа собрать карту в Phaser 4 — и какой когда брать

**Способ 1. `tileSprite` (текущий).** Один спрайт, повторяющий текстуру по
всему прямоугольнику. Годится ровно для однородных заливок (вода, ровная
трава) и для полосы из одного и того же куска. Не годится для карты с
кромками и разной высотой: повтор не даёт стыков.

**Способ 2. Статические `Image` — деталь к детали.** Для набора из
блоков это то, что нужно: раскладываем готовые куски как картинки.

```ts
// Плоское пятно травы 4x3 тайла из левой группы листа (индекс кадра = ряд * 9 + столбец)
const patch = this.add.image(x, y, 'arena-tiles', frame).setOrigin(0, 0).setDisplaySize(4 * 64, 3 * 64);
```

Плюс: полный контроль над композицией. Минус: много объектов, если карта
большая — тогда стоит переходить к способу 3.

**Способ 3. `Tilemap` + `createDynamicLayer` (для настоящих карт).**

```ts
const map = this.make.tilemap({ tileWidth: 64, tileHeight: 64 });
const tiles = map.addTilesetImage('arena', 'arena-tiles', 64, 64, 0, 0);
const layer = map.createDynamicLayer(0, tiles, 0, DEPTH.GROUND);
layer.putTileAt(frameIndex, x, y);
```

`frameIndex` = `ряд * 9 + столбец` (тайлсет 9×6). Каждая пара «слой
возвышенности + слой тени под ней» — свой `createDynamicLayer` со своим
`setDepth`. Слои статичны, поэтому Phaser перерисовывает их только при
изменении — это дёшево.

### Правило тени, в коде

```ts
// Shadow 192×192 кладётся на площадь 64×64 и сдвигается на тайл вниз
const shadow = this.add.image(tileX, tileY + 64, 'shadow').setDisplaySize(192, 192);
```

Важно: тень должна быть **ниже** земли по глубине и сдвинута по `y` на
`+64`, а не по глубине. Сдвиг по глубине даст плоскую тень без высоты.

### Правило пены, в коде

```ts
// Случайный сдвиг фазы: без него вся пена пульсирует синхронно
const phase = Phaser.Math.Between(0, 15);
f.play({ key: 'fx-foam', startFrame: phase });
```

### Декор — только на плоской земле

Деревья, кусты, камни и пни в нашем проекте ставятся вручную кодом. По
гайду они относятся к содержимому слоя Flat Ground: если появится
возвышенность, декор на ней должен отличаться (другим цветом тайлсета) и
никогда не ставиться на обрыв — иначе дерево «вырастет» из стены.

## 4. Ограничения геймплея (важно для карт)

Игра — bullet-heaven, а не платформер:

- мир — квадрат `WORLD.SIZE`, трава занимает всё внутри отступов
  `WORLD.GRASS_MARGIN = 160`, дальше вода;
- враги преследуют игрока напрямую (никакой навигации), предметы и
  враги спавнятся в кольце вокруг игрока и удерживаются внутри границ
  `GRASS_MARGIN + 20…60` (`GameScene`, `Enemy`, `Spawner`);
- физики столкновений с рельефом нет.

Отсюда правило: **возвышенности в нашей игре могут быть только
косметическими.** Если нарисовать ступени, по которым игрок ходит, но
враги не учитывают высоту, толпа начнёт «проваливаться» в обрывы
визуально. Правильный путь для полноценной карты с перепадами — завести
сетку проходимости и одинаково ограничивать ею и игрока, и спавн, и
преследование; это отдельная задача, а не разовая правка тайлсета.

## 5. Чек-лист «добавить уровень»

1. Определить размер в тайлах и положить его в `WORLD` (кратно 64,
   иначе `tileSprite` обрежет полосу).
2. Разметить слои в порядке гайда: вода → пена → плоская земля → пары
   (тень, возвышенность) по числу уровней.
3. Каждый следующий слой земли брать из другого `tilemap-colorN.png` —
   перепад высоты должен читаться цветом.
4. Под каждым куском возвышенности положить `shadow.png`, сдвинув на
   64 px вниз.
5. Пену положить только по кромке воды, каждому спрайту — свою фазу.
6. Обрывы различать: к воде — один вид детали, к проходимой земле —
   другой. Для перехода между уровнями использовать лестницы (одна
   деталь сверху, две — если рядом обрыв).
7. Декор расставить только на плоской земле, не ближе одного тайла к
   обрыву и к воде.
8. Проверить, что границы проходимости совпадают с `GRASS_MARGIN`, иначе
   игрок или враги будут «ходить по воде».
9. Проверить рендер на 1280×800 и на мобильном полотне 460×800: тайлы
   64 px должны попадать в целые пиксели камеры, иначе появится «мыло».

## 6. Подводные камни, на которые уже наступали

- **Индекс кадра = `ряд * 9 + столбец`.** Тайлсет 9×6; при смене набора
  или на другую цветовую схему ширина сетки меняется — индексы надо
  пересчитать.
- **`frameWidth/frameHeight` в загрузке.** Для `arena-tiles` это 64×64, для
  `fx-foam` — 192×192, для спрайт-листов юнитов — 192×192, а у копейщика
  320×320. Ошибка в размере кадра ломает анимацию целиком.
- **Тени юнитов и тайлмапные тени — разные вещи.** `shadow.png` из
  тайлсета (192×192, для рельефа) и `game/shadow-soft.png` (для
  персонажей) — разные ассеты с разными правилами; путать их нельзя.
- **`tileSprite` с одним кадром и поворотом** (текущая кромка арены) —
  рабочий приём для прямых участков, но не для углов и не для
  произвольной формы: при повороте на 90° текстура едет, а стыки
  рассыпаются.
- **Полупрозрачные зазоры в листе.** У кусков есть прозрачные поля; при
  сборке карты их нельзя перекрывать соседями вплотную — иначе появится
  тёмная полоса на стыке.

## 7. Полезные скрипты

- `scripts/prepare-assets.mjs` — подготовка производных текстур
  (девятислайсы, полосы, углы рамки, мечи логотипа).
- `scripts/lib/png.mjs` — `decodePng`, `contentBounds`, `blit`, `crop`:
  на них удобно мерить сетку тайлсета и проверять прозрачные зазоры.
- `scripts/probe-cursors.mjs` — пример того, как в этом проекте меряют
  ассеты по непрозрачным пикселям. Для тайлсета приём тот же: печатать
  карту листа по сетке 64 px и сверять с визуалом.
